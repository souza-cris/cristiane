{%- comment -%} Machine-readable statements about what this page is. Kept out of head.html because it is a different kind of thing — a block of statements rather than a list of tags — and mixing them makes both harder to read. Every address here is the `page_url` head.html already computed, so a structured statement can never name a different address from the canonical. Four shapes: home → a Person, so a search engine can tell whose site this is /journey → a ProfilePage about that same Person, with her education and employment derived from _data/journey.yml a story → a BlogPosting, with its title, dates and image /research → a list of ScholarlyArticles. Publications are entries in _data/research.yml, not pages, so each names its own external record rather than an address on this site. Both Person entities read _data/profile.yml and _data/social.yml, so they cannot drift apart and describe two different people. A BreadcrumbList is added at the end for anything below the top level. This is data, not a script. Nothing here runs, and nothing is fetched. {%- endcomment -%} {%- comment -%} Everywhere that is also her, in one list: the footer links plus the ORCID. Built once here so the home Person and the journey Person quote the same one. {%- endcomment -%} {%- capture same_as -%} {%- for link in site.data.social %}{{ link.url | jsonify }},{% endfor -%} {{ site.data.profile.orcid | jsonify }} {%- endcapture -%} {%- if page.url == '/' -%} {%- elsif page.url == '/journey/' -%} {%- comment -%} The journey page is a profile, so it says so. Everything below is DERIVED from _data/journey.yml rather than restated: the schools are the `academia` stops and the current affiliation is the most recent one. Add a milestone to the track and this updates with it, which is the point — a claim here can never contradict the page a visitor is looking at. Organizations are de-duplicated by name, because two degrees from the same university are two stops on the track but one alumniOf. The `industry` stops are deliberately NOT emitted. The task asked for employment, and schema.org's only field for it is `worksFor`, which means where a person works NOW — it has no past-employer equivalent. Deriving it from the track would have told a search engine she currently works at seven companies at once, all of which she has left. A tidy-looking claim that is false is worse than no claim, so the industry half of the track stays visible on the page and out of the markup. {%- endcomment -%} {%- assign academia = site.data.journey | where: 'category', 'academia' -%} {%- assign schools = academia | map: 'org' | uniq -%} {%- assign current = academia | last -%} {%- assign profile_updated = page.updated | default: site.time -%} {%- elsif page.layout == 'story' -%} {%- comment -%} dateModified falls back to the publication date, so a story that has not been revised says so honestly rather than claiming today. {%- endcomment -%} {%- elsif page.url == '/research/' and site.data.research.publications -%} {%- endif -%} {%- comment -%} Breadcrumbs, for anything that is not the home page. Each address is built with absolute_url from the same values the navigation uses, so a breadcrumb cannot point somewhere the site does not serve. The 404 gets none: it is not a location in the site's structure. {%- endcomment -%} {%- unless page.url == '/' or page.url contains '404' -%} {%- endunless -%}
