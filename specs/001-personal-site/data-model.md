# Data Model: Personal Website

**Date**: 2026-07-25

## Entities

### Blog Post

A Markdown file in `_posts/` following Jekyll naming convention.

**File**: `_posts/YYYY-MM-DD-title-slug.md`

**Front matter fields**:

| Field | Required | Description |
|-------|----------|-------------|
| `layout` | Yes | Always `post` |
| `title` | Yes | Post title displayed on index and detail page |
| `date` | Yes | Publication date (YYYY-MM-DD HH:MM:SS) |
| `excerpt_separator` | No | Custom excerpt boundary (default: first paragraph) |

**Body**: Markdown content (the full post).

**Derived fields** (auto-generated by Jekyll):
- `post.excerpt` — first paragraph (used on blog index)
- `post.url` — permalink to the post detail page

---

### Project

A Markdown file in the `_projects/` collection.

**File**: `_projects/project-slug.md`

**Front matter fields**:

| Field | Required | Description |
|-------|----------|-------------|
| `layout` | Yes | Always `project` |
| `title` | Yes | Project name |
| `description` | Yes | Short description (shown on index page) |
| `date` | Yes | Project date (for ordering, newest first) |
| `images` | No | List of image paths relative to `/assets/images/` |
| `links` | No | List of objects with `label` and `url` (e.g., GitHub repo, live demo) |
| `tools` | No | List of tools/technologies used or learned |

**Body**: Markdown content (detailed project write-up including "what I used/learned").

**Collection config** (in `_config.yml`):
```yaml
collections:
  projects:
    output: true
    sort_by: date
    order: descending
```

### Curation Item

An entry in `_data/curation.yml`.

**Structure**:

```yaml
- category: "Books"
  items:
    - title: "Example Book"
      url: "https://example.com"
      note: "Why I recommend this"
    - title: "Another Book"
      url: "https://example.com"
      note: "Short recommendation note"

- category: "Tools"
  items:
    - title: "Example Tool"
      url: "https://example.com"
      note: "What I use it for"
```

| Field | Required | Description |
|-------|----------|-------------|
| `category` | Yes | Grouping label (e.g., Books, Tools, Articles) |
| `items` | Yes | List of items in the category |
| `items[].title` | Yes | Display name of the recommended resource |
| `items[].url` | Yes | External link to the resource |
| `items[].note` | Yes | Short explanation of why it is recommended |

---

### Profile Links

Stored in `_config.yml` under a custom key.

**Structure** (in `_config.yml`):

```yaml
title: "Cristiane"
description: "One-line description of who I am"
photo: "/assets/images/profile.jpg"
email: "cristiane@example.com"

social:
  - label: "GitHub"
    url: "https://github.com/souza-cris"
  - label: "LinkedIn"
    url: "https://linkedin.com/in/cristiane"
```

| Field | Required | Description |
|-------|----------|-------------|
| `title` | Yes | Site title / author name |
| `description` | Yes | One-line personal description |
| `photo` | Yes | Path to profile photo |
| `email` | No | Contact email (used on portfolio page) |
| `social` | Yes | List of external profile links |
| `social[].label` | Yes | Display label (e.g., "GitHub") |
| `social[].url` | Yes | External profile URL |

## Relationships

```text
_config.yml (site metadata, profile links)
    └── Referenced by: default layout (nav, footer, home page)

_posts/*.md (blog posts)
    └── Listed by: blog.md index page
    └── Rendered by: post.html layout

_projects/*.md (project pages)
    └── Listed by: projects.md index page
    └── Rendered by: project.html layout

_data/curation.yml (curation items)
    └── Rendered by: curation.md page

assets/files/resume.pdf
    └── Linked from: portfolio.md page (conditional on file existence)
```

## Validation Rules

- Blog posts MUST follow Jekyll naming: `YYYY-MM-DD-title-slug.md`
- Blog posts MUST include `layout: post`, `title`, and `date` in front matter
- Project files MUST include `layout: project`, `title`, `description`, and `date` in front matter
- Curation items MUST have `title`, `url`, and `note`; categories MUST have at least one item
- Profile links MUST have both `label` and `url`
- All image paths MUST point to files in `assets/images/`
